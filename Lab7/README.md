# Лабораторна 7. Узагальнені алгоритми

Запуск із цієї папки: `dotnet run -c Release`.

Один і той самий `Filter` відбирає числа, слова й студентів. Тіло алгоритму між трьома викликами змінюється 0 разів. Ланцюжок `Filter → Map` спочатку лишає числа, кратні трьом, і потім ставить їх у дужки.

## Агрегації

**Сума**
- Стан — поточна сума.
- Старт — 0.
- Крок — додати поточне число.

**Добуток**
- Стан — поточний добуток, тип `BigInteger`.
- Старт — 1.
- Крок — помножити на поточне число.

**Максимум**
- Стан — найбільше побачене число або `null`.
- Старт — `null`.
- Крок — взяти поточне число, якщо стан порожній або число більше.

**Елемент із найбільшим модулем**
- Стан — число з найбільшим модулем, зі знаком.
- Старт — 0.
- Крок — замінити стан, якщо модуль поточного числа більший. При рівності лишається попереднє число.

## Захоплення змінних

1. `Поріг: True -> False`. Обидва виклики перевіряють число 7. Лямбда читає ту саму змінну, значення якої між викликами змінилося з 6 на 1000.
2. `for (3): 3, 3, 3`. Усі три делегати захопили спільний лічильник. Після циклу його значення дорівнює 3. Виправлення — створити всередині тіла циклу `int copy = i;` і захопити `copy`.
3. `foreach (3): 0, 1, 2`. На кожній ітерації сучасний C# створює окрему змінну циклу. Делегати бачать три різні значення.

## Висновок

Для трьох пар «тип і критерій» у стилі Лабораторної 4 знадобилися б три окремі функції. Тут достатньо однієї функції й трьох делегатів. Якби три критерії застосовувалися до кожного з трьох типів і кожна умова була в тілі окремої функції, функцій стало б дев'ять.

У №6 немає потреби узагальнювати `GetInitialStudents`: це функція, що створює конкретний набір студентів для запуску. Заміна її типового результату параметром типу приховала б, які дані вона повертає.
